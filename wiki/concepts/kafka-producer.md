# Kafka Producer (Code Walkthrough)

## Overview

The producer is the **sending side** of [[kafka]]. A service that wants to announce something (a user registered, a ticket was purchased) builds a message and hands it to Kafka. Kafka stores it on a topic; any interested consumer can read it later — the producer never waits to see if a consumer is alive.

There are **two layers** of producer code:

1. A **shared `Producer`** in `services/shared/pkg/kafka/producer.go` — the generic Kafka plumbing used by every service.
2. **Per-service publishers** in `services/ticket/internal/publisher/publisher.go` and `services/user/internal/publisher/publisher.go` — thin wrappers that say *what* to publish and *where*.

The flow: `publisher → shared Producer.Publish() → Kafka topic`.

## The Wire Format (EventEnvelope)

Every message sent to Kafka is a JSON object built by the shared producer (`producer.go:11`):

```go
type EventEnvelope struct {
    EventID       string      `json:"event_id"`
    EventType     string      `json:"event_type"`
    Timestamp     string      `json:"timestamp"`
    CorrelationID string      `json:"correlation_id"`
    Payload       interface{} `json:"payload"`
}
```

`interface{}` just means "any type" — the payload is whatever event-specific data the publisher attaches. A real message on the wire looks like:

```json
{
  "event_id": "evt_1724873920311000000",
  "event_type": "ticket.purchased",
  "timestamp": "2026-08-12T10:00:00Z",
  "correlation_id": "abc-123",
  "payload": {
    "booking_ref": "TBK-ABCD1234",
    "user_id": 42,
    "event_id": 100,
    "event_name": "Test Event",
    "event_date": "2026-08-01 20:00:00",
    "venue": "Test Venue",
    "quantity": 2
  }
}
```

Notes for a Go beginner:
- The backtick tags (`json:"event_id"`) tell Go's JSON library which key name to use when encoding/decoding.
- `EventID` is generated by the producer (`generateEventID()`, `producer.go:73`) — a unique ID per message.
- `CorrelationID` is passed in by the calling service so a single user request can be traced across services (see [[service-decoupling]]).

## Shared Producer Walkthrough

### Creating the producer

```go
p, err := kafka.NewProducer(brokers)  // producer.go:23
```

This opens a connection config (`ConfigMap`) with three settings (`producer.go:24`):

| Setting | Value | Why |
|---------|-------|-----|
| `bootstrap.servers` | the broker address | Where to connect (e.g. `kafka:9092`) |
| `acks` | `all` | The broker must confirm the message is safely stored (not just received) |
| `retries` | `5` | Retry transient failures up to 5 times |

Go note: `NewProducer` returns **two values** — the producer and an `error`. Go code always checks the error explicitly; if it's non-nil, the call failed. That's why every constructor returns `(*Producer, error)`.

### Publishing a message

```go
func (p *Producer) Publish(topic string, key string, eventType string, correlationID string, payload interface{}) error
```

`(p *Producer)` is the **method receiver** — it means "this function belongs to the Producer type." The `*` means it's a pointer: the method can modify the producer. Inside, four things happen:

1. **Build the envelope** (`producer.go:36`) — fill in `EventID`, `Timestamp`, `CorrelationID`, `Payload`.
2. **Marshal to JSON** (`producer.go:44`) — `json.Marshal` converts the struct into bytes; this is what actually gets sent over the wire. Errors here mean the payload couldn't be serialized.
3. **Produce** (`producer.go:50`) — hand the message to the Kafka client with a target topic and a key. The key (`booking_ref` for purchases, `user_id` for registrations) determines which partition the message lands on; messages with the same key are ordered.
4. **Wait for the broker's ack** (`producer.go:59`) — this is the `<-deliveryChan` line:

   ```go
   deliveryChan := make(chan kafka.Event, 1)
   err = p.producer.Produce(&kafka.Message{...}, deliveryChan)
   e := <-deliveryChan
   ```

   A **channel** (`chan`) is Go's way of passing values between goroutines. Here it's used as a "call me back when done" mailbox: the Kafka client puts the delivery result in the channel, and `<-deliveryChan` **blocks** the function until that result arrives. Then `m.TopicPartition.Error` (`producer.go:61`) is checked — non-nil means the broker rejected the message, and the error is returned to the caller.

   This makes `Publish` **synchronous**: it does not return until Kafka has confirmed the write. That's why it can't run in tests without a real broker (see [[testing-strategy]]).

### Closing

```go
func (p *Producer) Close()  // producer.go:68
```

`Flush(10*1000)` forces any unsent messages out (up to 10s), then closes the connection. Called on shutdown.

## Per-Service Publishers

The publishers exist so each service can call a named, typed method instead of raw Kafka plumbing.

### Ticket publisher (`services/ticket/internal/publisher/publisher.go`)

```go
p.PublishTicketPurchased(bookingRef, userID, eventID, eventName, eventDate, venue, quantity, correlationID)
```

- Builds a **typed** `TicketPurchasedPayload` struct (`publisher.go:21`) — nice for catching mistakes at compile time.
- Publishes to topic **`ticket.purchased`** with `key = booking_ref` (`publisher.go:41`). The same `booking_ref` is used by the consumer for dedupe — see [[kafka-consumer]].

### User publisher (`services/user/internal/publisher/publisher.go`)

```go
p.PublishUserCreated(userID, emailHash, correlationID)
```

- Builds a plain `map[string]interface{}` payload (`publisher.go:22`) — a looser format than the ticket one.
- Publishes to topic **`user.created`** with `key = user_id` (`publisher.go:27`). No consumer yet; future services can subscribe.

## Known Gap: No Producer Tests

There are **no test files** for `producer.go`, `services/ticket/internal/publisher/publisher.go`, or `services/user/internal/publisher/publisher.go`. Two reasons:

1. `Publish` blocks on `<-deliveryChan` for a real broker ack — no embedded Kafka exists in the test suite.
2. The publishers hold a concrete `*kafka.Producer`, not an interface — so there's no seam to inject a fake.

Only the envelope serialization logic could be tested broker-free, and it isn't. This is a candidate for future work (extract a `Publisher` interface; add a real-broker test behind a build tag).
